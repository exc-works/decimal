# v0.8.0 发布说明

[所有语言](https://github.com/exc-works/decimal/blob/v0.8.0/docs/releases/v0.8.0.md#languages)

v0.8.0 确立了明确的数值契约，修复算术和超越函数的舍入，保证解码失败时原状态不变，
并减少常用操作的内存分配。相对 v0.7.0 存在行为变化，升级已有应用前请阅读迁移说明。

## 升级注意事项

| 范围 | 变化与处理方式 |
| --- | --- |
| 默认数学输出 scale | Sqrt、ApproxRoot、Ln、Log10、Exp 从 `max(input scale,30)` 改为 `max(input scale,20)`；Log2 从输入 scale 改为同样至少 20 位小数。需要固定输出位数时使用 WithPrec。 |
| 负整数幂 | 输入 scale 上的 RoundUp 改为 HalfEven：`3.00^-1` 变为 `0.33`，`New(2).Power(-1)` 变为 `0`。请在计算幂之前设置所需 scale。 |
| 计算失败 | 根、对数和 Exp 无法在预算内确认舍入时报告 `ErrNoConvergence`。检查返回错误；Log2 保留 panic API，新增 Log2WithPrec 显式返回错误。 |
| 错误与 panic | 数值 panic 类别现在使用 error 类型的哨兵错误。解码错误统一包装 ErrUnmarshal 并保留原因。更新字符串断言、错误字符串比较和最外层类型断言。 |
| Nullable 编码 | Valid=true 且 Decimal 未初始化时，JSON/XML/BSON 编码为有效零。需要 null 时使用 Valid=false。 |
| 解析与 YAML | 拒绝非法重复符号。YAML 数值解码保留源文本数字及解码器的标量语法，不再经过 float64。 |
| 表示形式 | 实例 Max/Min 在数值相等时保留第一个操作数。`%g/%G` 在舍入后选择表示法，包括指数进位。请核对依赖 scale 和文本的快照。 |

最低要求仍为 **Go 1.26.0+**。模块路径不变，没有移除 v0.7.0 的导出 API。
Binary 布局不变；紧凑编码仍不保证保留 scale 或初始化状态。
解码错误现在保留全部接收者状态，包括 NullDecimal.Valid。

详见[中文升级说明](https://github.com/exc-works/decimal/blob/v0.8.0/docs/upgrade-v0.8.0.zh.md)
及[英文升级说明](https://github.com/exc-works/decimal/blob/v0.8.0/docs/numeric-contract-migration.md)。

## 正确性与新增 API

- MulWithPrec 在指定输出 scale 上对精确乘积只舍入一次；扩展已舍入乘积的 scale 无法恢复丢失的数字。
- Log2WithPrec 提供显式输出 scale 和错误处理。
- 除法直接在最终 scale 上舍入；`16.0 / 11` 在 scale 0 上 HalfEven 舍入为 `1`。负整数幂保留精确分母至最终舍入。
- 根使用精确整数中点判定，并改进高次根的上界。对数和指数通过向外舍入区间及显式级数尾项确认 HalfEven 结果。
- 解码失败具有原子性；在 scale 运算溢出之前检查数值溢出；快速路径也拒绝非法舍入模式。

[数值契约](https://github.com/exc-works/decimal/blob/v0.8.0/docs/numeric-contract.md)定义行为规则。
CI 包含独立精确有理数/区间证书、45 个必须成功的用例、有界算术/根 fuzz、race、
BSON 和 mapstructure 集成测试，以及 amd64/386 正确性检查。
这些检查覆盖承诺成功的用例及失败行为；任意输入仍受已记录的计算预算约束。

## 性能

整数查询避免计算不用的除法结果；整数转浮点避免构造有理数。
有理数转换和有效数字舍入复用独立拥有的缓冲区，有符号舍入共用一套实现。
对数/指数循环复用临时空间并使用有界的参数规约。这些优化没有引入新的全局缓存或共享可变临时空间。

最终优化 stack 在 Go 1.26.6、darwin/arm64 上的代表性分配变化：整数查询每次 3 → 0 次；
整数 Float64 7 → 0；整数 BigRat 精确构造 10 → 2；负数 HalfEven Rescale 9 → 4。
比较基线见[benchmark 报告](https://github.com/exc-works/decimal/blob/v0.8.0/docs/allocation-benchmarks.md)，
并非统一与 v0.7.0 比较，也不保证所有输入都有相同收益。
