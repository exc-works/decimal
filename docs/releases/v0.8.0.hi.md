# v0.8.0 रिलीज़ नोट्स

[सभी भाषाएँ](https://github.com/exc-works/decimal/blob/v0.8.0/docs/releases/v0.8.0.md#languages)

v0.8.0 स्पष्ट संख्यात्मक अनुबंध स्थापित करता है, अंकगणित और ट्रान्सेंडेंटल फ़ंक्शन की
राउंडिंग सुधारता है, डिकोडिंग विफल होने पर स्थिति सुरक्षित रखता है और सामान्य ऑपरेशन
में मेमोरी आवंटन घटाता है। v0.7.0 से व्यवहार बदलता है; मौजूदा एप्लिकेशन अपडेट करने
से पहले अपग्रेड मार्गदर्शिका पढ़ें।

## अपग्रेड करते समय ध्यान दें

| क्षेत्र | बदलाव और कार्रवाई |
| --- | --- |
| गणितीय आउटपुट का डिफ़ॉल्ट scale | Sqrt, ApproxRoot, Ln, Log10 और Exp का `max(input scale,30)` अब `max(input scale,20)` होता है। Log2 भी इनपुट scale की जगह वही न्यूनतम 20 दशमलव स्थान अपनाता है। स्पष्ट आवश्यकता के लिए WithPrec प्रयोग करें। |
| ऋणात्मक पूर्णांक घात | इनपुट scale पर RoundUp की जगह HalfEven होता है: `3.00^-1` अब `0.33` और `New(2).Power(-1)` अब `0` होता है। घात निकालने से पहले आवश्यक scale तय करें। |
| गणना विफलता | बजट में राउंडिंग प्रमाणित न कर पाने पर मूल, लघुगणक और Exp `ErrNoConvergence` देते हैं। लौटाई गई त्रुटि जाँचें; Log2 की panic API बनी रहती है और Log2WithPrec स्पष्ट त्रुटि प्रबंधन देता है। |
| त्रुटियाँ और panic | संख्यात्मक panic श्रेणियाँ अब error प्रकार के sentinel देती हैं। डिकोडिंग त्रुटियाँ कारण सुरक्षित रखते हुए ErrUnmarshal को लपेटती हैं। string type assertions, त्रुटि संदेशों की तुलना और सबसे बाहरी प्रकार के assertions अपडेट करें। |
| Nullable एन्कोडिंग | Valid=true और बिना आरंभ किया Decimal, JSON/XML/BSON में मान्य शून्य होता है। null के लिए Valid=false प्रयोग करें। |
| पार्सिंग और YAML | अमान्य दोहराए गए चिह्न अस्वीकार होते हैं। YAML संख्याएँ float64 से गुज़रे बिना मूल अंक और डिकोडर की scalar syntax सुरक्षित रखती हैं। |
| निरूपण | समान मान होने पर instance Max/Min पहला operand रखते हैं। `%g/%G` घातांक में carry सहित राउंडिंग के बाद notation चुनता है। scale या पाठ पर निर्भर snapshots जाँचें। |

न्यूनतम आवश्यकता **Go 1.26.0+** ही है। मॉड्यूल पथ नहीं बदलता और v0.7.0 की कोई
exported API हटाई नहीं जाती। Binary लेआउट समान है; संक्षिप्त एन्कोडिंग scale या
आरंभीकरण स्थिति सुरक्षित रखने की गारंटी नहीं देती। डिकोडिंग त्रुटियाँ NullDecimal.Valid
सहित प्राप्तकर्ता की पूरी स्थिति सुरक्षित रखती हैं।

[अंग्रेज़ी अपग्रेड मार्गदर्शिका](https://github.com/exc-works/decimal/blob/v0.8.0/docs/numeric-contract-migration.md)
या [सरलीकृत चीनी मार्गदर्शिका](https://github.com/exc-works/decimal/blob/v0.8.0/docs/upgrade-v0.8.0.zh.md) पढ़ें।

## शुद्धता और नई API

- MulWithPrec सटीक गुणनफल को माँगे गए scale पर केवल एक बार round करता है; पहले से round किए गुणनफल का scale बढ़ाने से खोए अंक नहीं लौटते।
- Log2WithPrec आउटपुट scale का स्पष्ट चुनाव और त्रुटि प्रबंधन देता है।
- भाग सीधे अंतिम scale पर round होता है; scale 0 और HalfEven के साथ `16.0 / 11` का परिणाम `1` है। ऋणात्मक घात अंतिम rounding तक सटीक हर बनाए रखते हैं।
- मूल सटीक पूर्णांक मध्यबिंदु तुलना और ऊँची घातों के लिए बेहतर ऊपरी सीमा प्रयोग करते हैं। लघुगणक और exponential, बाहर की ओर round किए अंतराल और श्रेणी के शेष की स्पष्ट सीमाओं से HalfEven प्रमाणित करते हैं।
- डिकोडिंग विफलता atomic है; scale गणना overflow होने से पहले जाँच होती है और तेज़ पथ भी अमान्य rounding modes अस्वीकार करते हैं।

[संख्यात्मक अनुबंध](https://github.com/exc-works/decimal/blob/v0.8.0/docs/numeric-contract.md)
नियम तय करता है। CI में स्वतंत्र सटीक परिमेय/अंतराल प्रमाण, 45 अनिवार्य सफल मामले,
सीमित अंकगणित/मूल fuzz, race, BSON और mapstructure integration tests तथा
amd64/386 शुद्धता जाँच शामिल हैं। ये वादा किए गए सफल मामलों और विफलता व्यवहार
को जाँचते हैं; सामान्य इनपुट अभी भी दस्तावेज़ित गणना बजट के अधीन हैं।

## प्रदर्शन

पूर्णांक जाँच अनावश्यक भाग परिणाम नहीं निकालती और पूर्णांक से floating-point
रूपांतरण परिमेय संख्या नहीं बनाता। परिमेय रूपांतरण और सार्थक अंकों की rounding
स्वतंत्र स्वामित्व वाले buffers दोबारा प्रयोग करते हैं; signed rounding एक implementation
साझा करती है। लघुगणक/exponential loops अस्थायी स्थान दोबारा प्रयोग करते हैं और
सीमित argument reduction करते हैं। कोई नया global cache या साझा mutable scratch नहीं जोड़ा गया है।

अंतिम optimization stack में Go 1.26.6, darwin/arm64 पर प्रतिनिधि आवंटन:
पूर्णांक जाँच 3 → 0 प्रति ऑपरेशन; पूर्णांक Float64 7 → 0; पूर्णांक BigRat का सटीक
निर्माण 10 → 2; ऋणात्मक HalfEven Rescale 9 → 4। आधार संस्करण
[benchmark रिपोर्ट](https://github.com/exc-works/decimal/blob/v0.8.0/docs/allocation-benchmarks.md)
में हैं; यह हर तुलना में v0.7.0 को आधार मानना या सभी इनपुट के लिए गारंटी देना नहीं है।
