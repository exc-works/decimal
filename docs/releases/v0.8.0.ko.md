# v0.8.0 릴리스 노트

[모든 언어](https://github.com/exc-works/decimal/blob/v0.8.0/docs/releases/v0.8.0.md#languages)

v0.8.0은 명확한 수치 계약을 확립하고 산술 연산 및 초월함수의 반올림을 수정합니다.
디코딩 실패 시 기존 상태를 보존하며 일반적인 연산의 메모리 할당을 줄입니다.
v0.7.0과 동작이 달라지므로 기존 애플리케이션을 업데이트하기 전에 업그레이드 안내를 확인하세요.

## 업그레이드 주의 사항

| 영역 | 변경 및 대응 |
| --- | --- |
| 수학 함수의 기본 scale | Sqrt, ApproxRoot, Ln, Log10, Exp가 `max(input scale,30)`에서 `max(input scale,20)`으로 변경됩니다. Log2도 입력 scale에서 같은 최소 소수 20자리로 변경됩니다. 출력 자릿수는 WithPrec로 명시하세요. |
| 음의 정수 거듭제곱 | 입력 scale에서 RoundUp 대신 HalfEven을 사용합니다. `3.00^-1`은 `0.33`, `New(2).Power(-1)`은 `0`이 됩니다. 거듭제곱을 계산하기 전에 필요한 scale을 설정하세요. |
| 계산 실패 | 예산 내에서 반올림을 보증할 수 없는 근, 로그, Exp는 `ErrNoConvergence`를 보고합니다. 반환 오류를 확인하세요. Log2의 panic API는 유지되며 Log2WithPrec가 명시적 오류 처리를 제공합니다. |
| 오류와 panic | 수치 panic 범주는 error 타입의 센티널을 제공합니다. 디코딩 오류는 원인을 보존하며 ErrUnmarshal로 래핑됩니다. 문자열 단언, 오류 문자열 비교, 최외곽 타입 단언을 수정하세요. |
| Nullable 인코딩 | Valid=true이고 Decimal이 초기화되지 않았으면 JSON/XML/BSON에서 유효한 0으로 인코딩됩니다. null에는 Valid=false를 사용하세요. |
| 파싱과 YAML | 잘못된 반복 부호를 거부합니다. YAML 수치는 float64를 거치지 않고 원문 숫자와 디코더의 스칼라 문법을 보존합니다. |
| 표현 | 인스턴스 Max/Min은 값이 같으면 첫 피연산자를 유지합니다. `%g/%G`는 지수 올림을 포함해 반올림 후 표기법을 선택합니다. scale 및 텍스트에 의존하는 스냅샷을 확인하세요. |

최소 요구 사항은 여전히 **Go 1.26.0+**입니다. 모듈 경로는 그대로이며 v0.7.0의 공개 API를 제거하지 않았습니다.
Binary 레이아웃은 같지만 간결한 인코딩은 scale이나 초기화 상태 보존을 보장하지 않습니다.
디코딩 오류는 NullDecimal.Valid를 포함한 수신자의 모든 상태를 보존합니다.

[영문 업그레이드 안내](https://github.com/exc-works/decimal/blob/v0.8.0/docs/numeric-contract-migration.md)
또는 [중국어 간체 안내](https://github.com/exc-works/decimal/blob/v0.8.0/docs/upgrade-v0.8.0.zh.md)를 참고하세요.

## 정확성과 새로운 API

- MulWithPrec는 정확한 곱을 지정한 scale에서 한 번만 반올림합니다. 이미 반올림된 곱의 scale을 늘려도 잃은 자릿수는 복구되지 않습니다.
- Log2WithPrec는 출력 scale 지정과 오류 처리를 제공합니다.
- 나눗셈은 최종 scale에서 직접 반올림합니다. `16.0 / 11`을 scale 0에서 HalfEven으로 반올림하면 `1`입니다. 음의 정수 거듭제곱은 최종 반올림까지 정확한 분모를 유지합니다.
- 근은 정확한 정수 중점 판정을 사용하고 고차근의 상한도 개선합니다. 로그와 지수는 바깥쪽 반올림 구간과 명시적 급수 나머지로 HalfEven 결과를 보증합니다.
- 디코딩 실패는 원자적입니다. scale 연산의 오버플로 전에 검사하며 빠른 경로에서도 잘못된 반올림 모드를 거부합니다.

[수치 계약](https://github.com/exc-works/decimal/blob/v0.8.0/docs/numeric-contract.md)이 규칙을 정의합니다.
CI는 독립적인 정확한 유리수/구간 증명, 반드시 성공해야 하는 45개 사례, 제한된 산술/근 fuzz,
race, BSON 및 mapstructure 통합 테스트와 amd64/386 정확성 검사를 결합합니다.
이 검사는 약속된 성공 사례와 실패 동작을 다루며 임의의 입력에는 문서화된 계산 예산이 적용됩니다.

## 성능

정수 검사는 사용하지 않는 나눗셈 결과를 계산하지 않고, 정수의 부동소수점 변환은 유리수 생성을 생략합니다.
유리수 변환과 유효숫자 반올림은 독립적으로 소유한 버퍼를 재사용하며 부호 있는 반올림은 하나의 구현을 공유합니다.
로그/지수 루프는 임시 공간을 재사용하고 제한된 인수 축소를 적용합니다. 새 전역 캐시나 공유 가변 임시 공간은 도입하지 않습니다.

최종 최적화 stack의 Go 1.26.6, darwin/arm64 대표 할당 횟수: 정수 검사 3 → 0회/연산,
정수 Float64 7 → 0, 정수 BigRat의 정확한 생성 10 → 2, 음수 HalfEven Rescale 9 → 4.
비교 기준은 [benchmark 보고서](https://github.com/exc-works/decimal/blob/v0.8.0/docs/allocation-benchmarks.md)에 있습니다.
모두 v0.7.0과 비교한 수치가 아니며 모든 입력에 대한 보장도 아닙니다.
