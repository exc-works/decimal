# Notes de version v0.8.0

[Toutes les langues](https://github.com/exc-works/decimal/blob/v0.8.0/docs/releases/v0.8.0.md#languages)

v0.8.0 établit un contrat numérique explicite, corrige l'arrondi des opérations
arithmétiques et des fonctions transcendantes, préserve l'état en cas d'échec du
décodage et réduit les allocations mémoire. Le comportement change par rapport
à v0.7.0 ; consultez le guide de migration avant de mettre à jour une application.

## Points d'attention pour la migration

| Domaine | Changement et action |
| --- | --- |
| Échelle mathématique par défaut | Sqrt, ApproxRoot, Ln, Log10 et Exp passent de `max(input scale,30)` à `max(input scale,20)`. Log2 passe de l'échelle d'entrée au même minimum de 20 décimales. Utilisez WithPrec pour une exigence explicite. |
| Puissances entières négatives | HalfEven remplace RoundUp à l'échelle d'entrée : `3.00^-1` devient `0.33` ; `New(2).Power(-1)` devient `0`. Définissez l'échelle requise avant le calcul. |
| Échec du calcul | Les racines, logarithmes et Exp signalent `ErrNoConvergence` si l'arrondi ne peut être certifié dans le budget. Vérifiez les erreurs ; Log2 conserve son API avec panic et ajoute Log2WithPrec pour un traitement explicite des erreurs. |
| Erreurs et panic | Les catégories de panic numérique exposent des erreurs sentinelles de type error. Les erreurs de décodage enveloppent ErrUnmarshal en préservant leur cause. Mettez à jour les assertions de chaîne, les comparaisons de messages et les assertions sur le type externe. |
| Encodage nullable | Valid=true avec un Decimal non initialisé représente un zéro valide en JSON/XML/BSON. Utilisez Valid=false pour null. |
| Analyse et YAML | Les répétitions de signes invalides sont rejetées. YAML préserve les chiffres sources et la syntaxe scalaire du décodeur sans passer par float64. |
| Représentations | Les méthodes Max/Min conservent le premier opérande en cas d'égalité. `%g/%G` choisit la notation après l'arrondi, y compris lors d'une retenue sur l'exposant. Vérifiez les instantanés sensibles à l'échelle ou au texte. |

La version minimale reste **Go 1.26.0+**. Le chemin du module ne change pas et
aucune API exportée de v0.7.0 n'est supprimée. La disposition Binary reste
identique ; les encodages compacts ne garantissent pas la conservation de
l'échelle ni de l'initialisation. Les erreurs de décodage préservent tout l'état
du récepteur, y compris NullDecimal.Valid.

Consultez le [guide en anglais](https://github.com/exc-works/decimal/blob/v0.8.0/docs/numeric-contract-migration.md)
ou le [guide en chinois simplifié](https://github.com/exc-works/decimal/blob/v0.8.0/docs/upgrade-v0.8.0.zh.md).

## Exactitude et nouvelles API

- MulWithPrec arrondit le produit exact une seule fois à l'échelle demandée ; augmenter l'échelle d'un produit déjà arrondi ne restitue pas les chiffres perdus.
- Log2WithPrec permet de préciser l'échelle de sortie et de traiter les erreurs.
- La division arrondit directement à l'échelle finale : `16.0 / 11` à l'échelle 0 avec HalfEven donne `1`. Les puissances négatives gardent le dénominateur exact jusqu'à l'arrondi final.
- Les racines utilisent des comparaisons exactes aux points médians entiers et une meilleure borne supérieure pour les degrés élevés. Logarithmes et exponentielles certifient HalfEven à l'aide d'intervalles arrondis vers l'extérieur et de bornes explicites du reste des séries.
- Les échecs de décodage sont atomiques ; le dépassement est contrôlé avant celui du calcul d'échelle et les chemins rapides rejettent les modes d'arrondi invalides.

Le [contrat numérique](https://github.com/exc-works/decimal/blob/v0.8.0/docs/numeric-contract.md)
définit les règles. La CI combine des certificats indépendants par rationnels
exacts et intervalles, 45 cas devant réussir, du fuzz borné sur l'arithmétique et
les racines, les tests race, BSON et mapstructure, ainsi que l'exactitude sur
amd64/386. Ces vérifications couvrent les succès promis et le comportement en
échec ; toute entrée reste soumise aux budgets de calcul documentés.

## Performances

Les inspections d'entiers évitent les résultats de division inutilisés ; leur
conversion flottante évite de construire des rationnels. Les conversions
rationnelles et l'arrondi des chiffres significatifs réutilisent des tampons
détenus indépendamment, et l'arrondi signé partage une implémentation. Les boucles
logarithmiques et exponentielles réutilisent l'espace temporaire et des réductions
d'argument bornées. Aucun nouveau cache global ni espace mutable partagé n'est introduit.

Allocations représentatives de la dernière série d'optimisations sous Go 1.26.6,
darwin/arm64 : inspections d'entiers 3 → 0 par opération ; Float64 entier 7 → 0 ;
construction exacte d'un BigRat entier 10 → 2 ; Rescale HalfEven négatif 9 → 4.
Les bases sont celles du [rapport de benchmarks](https://github.com/exc-works/decimal/blob/v0.8.0/docs/allocation-benchmarks.md),
et ne constituent ni une comparaison uniforme à v0.7.0 ni une garantie pour toute entrée.
