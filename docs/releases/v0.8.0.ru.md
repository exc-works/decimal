# Примечания к выпуску v0.8.0

[Все языки](https://github.com/exc-works/decimal/blob/v0.8.0/docs/releases/v0.8.0.md#languages)

v0.8.0 задаёт явный численный контракт, исправляет округление арифметических
операций и трансцендентных функций, сохраняет состояние при ошибке декодирования
и сокращает выделение памяти. Поведение отличается от v0.7.0; перед обновлением
существующих приложений прочитайте руководство по переходу.

## Что учитывать при обновлении

| Область | Изменение и действие |
| --- | --- |
| Масштаб математических результатов по умолчанию | Sqrt, ApproxRoot, Ln, Log10 и Exp переходят с `max(input scale,30)` на `max(input scale,20)`. Log2 переходит с масштаба входа на тот же минимум в 20 знаков после запятой. Для явных требований используйте WithPrec. |
| Отрицательные целые степени | HalfEven заменяет RoundUp при масштабе входа: `3.00^-1` становится `0.33`; `New(2).Power(-1)` становится `0`. Задайте нужный масштаб до возведения в степень. |
| Ошибки вычисления | Корни, логарифмы и Exp сообщают `ErrNoConvergence`, если нельзя подтвердить округление в пределах бюджета. Проверяйте ошибки; Log2 сохраняет API с panic и получает Log2WithPrec для явной обработки ошибок. |
| Ошибки и panic | Численные категории panic теперь представлены сигнальными значениями типа error. Ошибки декодирования оборачивают ErrUnmarshal, сохраняя причину. Обновите строковые утверждения типов, сравнения сообщений и утверждения внешнего типа ошибки. |
| Nullable-кодирование | Valid=true с неинициализированным Decimal означает допустимый ноль в JSON/XML/BSON. Для null используйте Valid=false. |
| Разбор и YAML | Некорректные повторяющиеся знаки отклоняются. YAML сохраняет исходные цифры и скалярный синтаксис декодера без промежуточного float64. |
| Представления | Методы Max/Min при равенстве значений сохраняют первый операнд. `%g/%G` выбирает форму записи после округления, включая перенос в показатель степени. Проверьте снимки, зависящие от масштаба или текста. |

Требование остаётся **Go 1.26.0+**. Путь модуля не меняется, экспортируемые API
v0.7.0 не удаляются. Формат Binary не меняется; компактное кодирование по-прежнему
не гарантирует сохранение масштаба или состояния инициализации. Ошибки
декодирования сохраняют всё состояние получателя, включая NullDecimal.Valid.

См. [руководство на английском](https://github.com/exc-works/decimal/blob/v0.8.0/docs/numeric-contract-migration.md)
или [на упрощённом китайском](https://github.com/exc-works/decimal/blob/v0.8.0/docs/upgrade-v0.8.0.zh.md).

## Корректность и новые API

- MulWithPrec округляет точное произведение один раз до заданного масштаба; увеличение масштаба уже округлённого произведения не восстанавливает потерянные цифры.
- Log2WithPrec предоставляет явный масштаб результата и обработку ошибок.
- Деление округляет сразу до конечного масштаба: `16.0 / 11` при масштабе 0 с HalfEven даёт `1`. Отрицательные степени сохраняют точный знаменатель до окончательного округления.
- Корни используют точные целочисленные сравнения средних точек и улучшенную верхнюю границу для высоких степеней. Логарифмы и экспоненты подтверждают HalfEven интервалами с округлением наружу и явными границами остатка ряда.
- Ошибки декодирования атомарны; переполнение проверяется до переполнения арифметики масштаба, а быстрые пути также отклоняют неверные режимы округления.

[Численный контракт](https://github.com/exc-works/decimal/blob/v0.8.0/docs/numeric-contract.md)
определяет правила. CI объединяет независимые сертификаты на точных рациональных
числах и интервалах, 45 обязательных успешных случаев, ограниченный fuzz для
арифметики и корней, race-тесты, интеграции BSON и mapstructure, а также проверки
корректности на amd64/386. Проверяются обещанные успехи и поведение при отказе;
произвольные входы по-прежнему ограничены документированными вычислительными бюджетами.

## Производительность

Проверки целых избегают неиспользуемых результатов деления; преобразование целых
в числа с плавающей точкой не строит рациональное число. Рациональные
преобразования и округление значащих цифр повторно используют независимо
принадлежащие им буферы, а округление со знаком использует общую реализацию.
Циклы логарифмов и экспонент переиспользуют временную память и ограниченную
редукцию аргумента. Новые глобальные кэши и общая изменяемая рабочая память не вводятся.

Примеры выделений памяти в последней серии оптимизаций на Go 1.26.6,
darwin/arm64: проверки целых 3 → 0 на операцию; Float64 целого 7 → 0;
точное создание целого BigRat 10 → 2; отрицательный HalfEven Rescale 9 → 4.
Базовые версии указаны в [отчёте benchmark](https://github.com/exc-works/decimal/blob/v0.8.0/docs/allocation-benchmarks.md).
Это не единое сравнение с v0.7.0 и не гарантия для всех входов.
