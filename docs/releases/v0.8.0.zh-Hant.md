# v0.8.0 發行說明

[所有語言](https://github.com/exc-works/decimal/blob/v0.8.0/docs/releases/v0.8.0.md#languages)

v0.8.0 確立明確的數值契約，修正算術與超越函數的捨入，確保解碼失敗時原狀態不變，
並減少常用操作的記憶體配置。相較 v0.7.0 有行為變更，升級既有應用程式前請閱讀遷移說明。

## 升級注意事項

| 範圍 | 變更與處理方式 |
| --- | --- |
| 預設數學輸出 scale | Sqrt、ApproxRoot、Ln、Log10、Exp 從 `max(input scale,30)` 改為 `max(input scale,20)`；Log2 從輸入 scale 改為同樣至少 20 位小數。需要固定輸出位數時使用 WithPrec。 |
| 負整數次方 | 輸入 scale 上的 RoundUp 改為 HalfEven：`3.00^-1` 變為 `0.33`，`New(2).Power(-1)` 變為 `0`。請在計算次方之前設定所需 scale。 |
| 計算失敗 | 根、對數與 Exp 無法在預算內確認捨入時回報 `ErrNoConvergence`。檢查回傳錯誤；Log2 保留 panic API，新增 Log2WithPrec 明確回傳錯誤。 |
| 錯誤與 panic | 數值 panic 類別現在使用 error 型別的哨兵錯誤。解碼錯誤統一包裝 ErrUnmarshal 並保留原因。更新字串斷言、錯誤字串比較及最外層型別斷言。 |
| Nullable 編碼 | Valid=true 且 Decimal 未初始化時，JSON/XML/BSON 編碼為有效零。需要 null 時使用 Valid=false。 |
| 解析與 YAML | 拒絕非法重複符號。YAML 數值解碼保留來源文字的數字與解碼器的純量語法，不再經過 float64。 |
| 表示形式 | 實例 Max/Min 在數值相等時保留第一個運算元。`%g/%G` 在捨入後選擇表示法，包括指數進位。請核對依賴 scale 與文字的快照。 |

最低需求仍為 **Go 1.26.0+**。模組路徑不變，未移除 v0.7.0 的匯出 API。
Binary 配置不變；緊湊編碼仍不保證保留 scale 或初始化狀態。
解碼錯誤現在保留接收者的全部狀態，包括 NullDecimal.Valid。

詳見[英文升級指南](https://github.com/exc-works/decimal/blob/v0.8.0/docs/numeric-contract-migration.md)
或[簡體中文升級說明](https://github.com/exc-works/decimal/blob/v0.8.0/docs/upgrade-v0.8.0.zh.md)。

## 正確性與新增 API

- MulWithPrec 在指定輸出 scale 上對精確乘積僅捨入一次；擴展已捨入乘積的 scale 無法恢復遺失的數字。
- Log2WithPrec 提供明確的輸出 scale 與錯誤處理。
- 除法直接在最終 scale 上捨入；`16.0 / 11` 在 scale 0 上 HalfEven 捨入為 `1`。負整數次方保留精確分母直到最終捨入。
- 根使用精確整數中點判定，並改進高次根的上界。對數與指數透過向外捨入區間及明確的級數尾項確認 HalfEven 結果。
- 解碼失敗具有原子性；在 scale 運算溢位前檢查數值溢位；快速路徑也拒絕非法捨入模式。

[數值契約](https://github.com/exc-works/decimal/blob/v0.8.0/docs/numeric-contract.md)定義行為規則。
CI 包含獨立精確有理數／區間證書、45 個必須成功的案例、有界算術／根 fuzz、race、
BSON 與 mapstructure 整合測試，以及 amd64/386 正確性檢查。
這些檢查涵蓋承諾成功的案例與失敗行為；任意輸入仍受已記載的計算預算約束。

## 效能

整數查詢避免計算未使用的除法結果；整數轉浮點避免建構有理數。
有理數轉換與有效數字捨入重用各自擁有的緩衝區，帶正負號的捨入共用一套實作。
對數／指數迴圈重用暫存空間並採用有界的引數縮減。這些最佳化未引入新的全域快取或共享可變暫存空間。

最終最佳化 stack 在 Go 1.26.6、darwin/arm64 上的代表性配置變化：整數查詢每次 3 → 0 次；
整數 Float64 7 → 0；整數 BigRat 精確建構 10 → 2；負數 HalfEven Rescale 9 → 4。
比較基準見[benchmark 報告](https://github.com/exc-works/decimal/blob/v0.8.0/docs/allocation-benchmarks.md)，
並非一律與 v0.7.0 比較，也不保證所有輸入都有相同收益。
