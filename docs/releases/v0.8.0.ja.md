# v0.8.0 リリースノート

[すべての言語](https://github.com/exc-works/decimal/blob/v0.8.0/docs/releases/v0.8.0.md#languages)

v0.8.0 は数値の契約を明確にし、算術演算と超越関数の丸めを修正します。
デコード失敗時の状態を保持し、一般的な操作のメモリ割り当てを削減します。
v0.7.0 から動作が変わるため、既存アプリケーションの更新前に移行ガイドを確認してください。

## アップグレード時の注意

| 対象 | 変更と対応 |
| --- | --- |
| 数学関数の既定スケール | Sqrt、ApproxRoot、Ln、Log10、Exp は `max(input scale,30)` から `max(input scale,20)` に変更。Log2 も入力スケールから同じ最小 20 桁の小数部に変更します。必要な桁数は WithPrec で指定してください。 |
| 負の整数乗 | 入力スケールで RoundUp の代わりに HalfEven を使います。`3.00^-1` は `0.33`、`New(2).Power(-1)` は `0` になります。累乗計算前に必要なスケールを設定してください。 |
| 計算失敗 | 予算内で丸めを保証できない根・対数・Exp は `ErrNoConvergence` を返します。エラーを確認してください。Log2 の panic API は維持し、Log2WithPrec で明示的なエラー処理を提供します。 |
| エラーと panic | 数値 panic の分類は error 型のセンチネルを公開します。デコードエラーは原因を保持して ErrUnmarshal でラップします。文字列アサーション、エラー文字列の比較、最外層の型アサーションを更新してください。 |
| Nullable エンコード | Valid=true で未初期化の Decimal は JSON/XML/BSON で有効なゼロになります。null には Valid=false を使ってください。 |
| パースと YAML | 不正な符号の繰り返しを拒否します。YAML 数値は float64 を経由せず、元の桁とデコーダーのスカラー構文を保持します。 |
| 表現 | 同値のインスタンス Max/Min は最初のオペランドを保持します。`%g/%G` は指数の繰り上がりも含め、丸め後に表記を選びます。スケールや文字列に依存するスナップショットを確認してください。 |

要件は引き続き **Go 1.26.0+** です。モジュールパスは変わらず、v0.7.0 の公開 API の削除もありません。
Binary のレイアウトは変わりませんが、コンパクトなエンコードはスケールや初期化状態の保持を保証しません。
デコードエラーは NullDecimal.Valid を含む受信側の全状態を保持します。

詳しくは[英語の移行ガイド](https://github.com/exc-works/decimal/blob/v0.8.0/docs/numeric-contract-migration.md)
または[簡体字中国語の移行ガイド](https://github.com/exc-works/decimal/blob/v0.8.0/docs/upgrade-v0.8.0.zh.md)を参照してください。

## 正確性と新しい API

- MulWithPrec は指定スケールで正確な積を一度だけ丸めます。丸め済みの積のスケールを増やしても失われた桁は戻りません。
- Log2WithPrec は出力スケールの指定とエラー処理を提供します。
- 除算は最終スケールで直接丸めます。`16.0 / 11` のスケール 0、HalfEven の結果は `1` です。負の整数乗は最終丸めまで正確な分母を保持します。
- 根は正確な整数の中点判定を使い、高次の根の上界も改善します。対数と指数は外向き丸め区間と明示的な級数の剰余で HalfEven を保証します。
- デコード失敗はアトミックです。スケール計算がオーバーフローする前に検査し、高速経路でも不正な丸めモードを拒否します。

[数値の契約](https://github.com/exc-works/decimal/blob/v0.8.0/docs/numeric-contract.md)が規則を定義します。
CI は独立した正確な有理数・区間の証明、成功必須の 45 ケース、有界の算術・根の fuzz、race、
BSON と mapstructure の統合テスト、amd64/386 の正確性検査を組み合わせます。
これらは約束された成功ケースと失敗動作を検査し、任意の入力は文書化された計算予算に従います。

## 性能

整数の検査は不要な除算結果を計算せず、整数から浮動小数点への変換は有理数の構築を省きます。
有理数変換と有効数字の丸めは独立所有のバッファを再利用し、符号付き丸めは一つの実装を共有します。
対数・指数のループは作業領域を再利用し、有界の引数還元を行います。新たなグローバルキャッシュや共有可変作業領域は導入しません。

最終最適化 stack の Go 1.26.6、darwin/arm64 での代表的な割り当て回数：整数の検査 3 → 0 回/操作、
整数 Float64 7 → 0、整数 BigRat の正確な構築 10 → 2、負数 HalfEven Rescale 9 → 4。
基準は[benchmark レポート](https://github.com/exc-works/decimal/blob/v0.8.0/docs/allocation-benchmarks.md)に記載されています。
一律に v0.7.0 と比較した結果でも、すべての入力への保証でもありません。
