v0.8.0 establishes an explicit numerical contract, corrects arithmetic and
transcendental rounding, preserves decoding state on failure, and reduces
allocations in common operations. It includes behavior changes from v0.7.0;
review the upgrade notes before updating existing applications.

## Upgrade attention

| Area | Change and action |
| --- | --- |
| Default mathematical scale | Sqrt, ApproxRoot, Ln, Log10, and Exp change from `max(input scale,30)` to `max(input scale,20)`. Log2 changes from input scale to that same minimum of 20. Use WithPrec methods for an explicit requirement. |
| Negative integer powers | HalfEven replaces RoundUp at the input scale: `3.00^-1` becomes `0.33`; `New(2).Power(-1)` becomes `0`. Supply the required scale before computing the power. |
| Calculation failure | Roots, logarithms, and Exp report `ErrNoConvergence` when rounding cannot be certified within their budget. Check returned errors; Log2 retains its panic API and gains Log2WithPrec for explicit error handling. |
| Errors and panics | Numeric panic categories now expose error-valued sentinels. Decoder errors consistently wrap ErrUnmarshal and preserve causes. Update string assertions, error-string comparisons, and outer type assertions. |
| Nullable encodings | Valid=true with an uninitialized Decimal is valid zero in JSON/XML/BSON. Use Valid=false for null. |
| Parsing and YAML | Malformed repeated signs are rejected. YAML numeric decoding preserves source digits and the decoder's scalar syntax instead of routing through float64. |
| Representations | Equal-valued instance Max/Min retain the first operand. `%g/%G` notation is selected after rounding, including exponent carries. Recheck scale-sensitive and textual snapshots. |

The Go requirement remains **Go 1.26.0+**. The module path is unchanged, and no
exported API is removed relative to v0.7.0. Binary layout is unchanged; compact
encodings still need not preserve scale or initialization state. Decoding errors
now preserve all receiver state, including NullDecimal.Valid.

## Correctness and new APIs

- `MulWithPrec` rounds the exact product once at an explicit output scale;
  rescaling an already rounded product cannot recover lost digits.
- `Log2WithPrec` provides explicit output scale and error handling.
- Division rounds directly at the final scale; `16.0 / 11` at scale 0 with
  HalfEven is `1`. Negative powers keep exact denominators through final rounding.
- Roots use exact integer midpoint decisions and an improved upper bound for
  high degrees. Logarithms and exponentials certify HalfEven rounding through
  outward intervals and explicit series tails.
- Decoder failures are atomic, numeric overflow is checked before scale
  arithmetic wraps, and invalid rounding modes are rejected on fast paths.

The [numerical contract](https://github.com/exc-works/decimal/blob/v0.8.0/docs/numeric-contract.md)
defines the rules. CI combines independent exact rational/interval certificates,
a 45-case must-succeed corpus, bounded arithmetic/root fuzzing, race tests,
BSON and mapstructure integration tests, and amd64/386 correctness checks.
These checks exercise the promised successful cases and failure behavior;
arbitrary inputs remain subject to documented calculation budgets.

## Performance

Integer inspection avoids unused division results; integer floating conversion
avoids rational construction. Rational conversion and significant-figure rounding
reuse independently owned buffers, and signed rounding shares one implementation.
Logarithm/exponential loops reuse scratch and choose bounded argument reductions.
No new global cache or shared mutable scratch is introduced by these optimizations.

Representative allocation changes from the final optimization stack on Go 1.26.6,
darwin/arm64: integer queries 3 → 0 allocs/op; integer Float64 7 → 0; exact integer
BigRat construction 10 → 2; negative HalfEven Rescale 9 → 4. These comparisons use
the baselines recorded in the [benchmark report](https://github.com/exc-works/decimal/blob/v0.8.0/docs/allocation-benchmarks.md),
not a blanket comparison with v0.7.0 or a guarantee for all inputs.
